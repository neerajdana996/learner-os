Two of these blocks are genuinely new. The rest is the code category with different pixels.
Category 2 of 5 · systems
This one is in the pilot
Consistency in distributed systems is one of the three pilot topics (T-058). Maths is not in the pilot at all — so of the two categories still to build, this is the one whose absence a real learner will feel in September.
It is also the one that costs the most: the interactive diagram cannot be rendered in the worker the way code and equations can, so this is the category where a library genuinely ships to the browser. That trade is argued on the spec page, not hidden in it.

diagram
context · new
Nodes and edges — a client, a load balancer, two replicas, the arrows between them. Rendered to SVG in the worker, because a diagram you only read does not need a graph library on the client.

sequence
context · new
Lanes and messages down a time axis. Half of distributed systems is an interleaving — a stale read is not a picture of boxes, it is two orders of events. A box diagram cannot show the bug this category is mostly about.
—
Yes, 2 lanes
graphBuild
answer · new
Places a component, or draws an edge. The answer is a graph, not a string or an index — grading asks whether the read path goes through the primary, not whether two pieces of text match. Nothing in the union bends into this; it is the one genuinely new grader.

No — needs a canvas
numeric
answer · new, shared
A number, with a tolerance. accept: string[] cannot express this — 6GB, 6e9 and 6,000,000,000 are one answer with infinitely many spellings, and a capacity estimate wants an order of magnitude, not equality. Maths needs exactly this block, which is why it is specified once.

Yes
Everything else ports unchanged. hotspot targets a node or an edge instead of a line; orderLines orders protocol steps instead of statements; recognition, explain and the whole reveal slot are identical. Two new blocks out of nine is the measure of whether the abstraction was right.
What the generator is told to pick, and when
The concept is a placement
Where the cache goes. Which side of the queue the retry lives on. Whether the read hits the primary.
→ graphBuild
The concept is an ordering
A stale read, a lost update, a write that overtook another. The bug is in the interleaving.
→ sequence + hotspot on a message
The concept is an inequality
Quorum: R + W > N. Replication lag budgets. Anything with a threshold.
→ numeric
The concept is a scale
“How much does 1M writes a day across 3 replicas actually move?” The point is the order of magnitude.
→ numeric, wide tolerance
The concept is a trade-off
Two designs that both work, for different prices. There is no shape to draw — the answer is a sentence.
→ diagram as context, explain as answer
The concept is a guarantee
What read-your-writes actually promises, and what it does not. A definition with a sharp edge.
→ recognition, options as scenarios
One answer block, even here
“Draw the architecture and justify the cache choice” is the request this category will keep making, and the answer is no: review_events.correct is one boolean and the scheduler needs one grade per item. Those become two items on the same concept — which is better retrieval practice anyway, so the constraint costs nothing. The domain fragment has to say this outright, because a model handed “design a system” will emit one item with five answers every time.
