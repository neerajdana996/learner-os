New concept · Read-your-writes
How to hold it
Read-your-writes is not a promise about the database. It is a promise about one session: whatever else is stale, you never see a version of the world older than your own last write. Everyone else may.
A
Two hundred milliseconds is not the bug. The bug is that a human clicks Save and then Refresh in about four hundred.
B
This is the only edge that has to change. Not the replication, not the database — the routing decision for this session's reads.
What the learner is actually going to hit
The user saved their name, got a 200, refreshed, and the old name came back. Nothing failed. Nothing logged an error. Every component behaved exactly as designed — which is why this is a design question and not a debugging one.
