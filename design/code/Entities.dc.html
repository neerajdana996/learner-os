What has to exist for any of this to render
Three new shapes, one new column each on two tables, and one prompt file per category.
Additive · nothing today breaks
1 · backend/src/shared/blocks.ts — the only place a block is defined
// context — read, never touched const CodeBlock = z.object({ kind: z.literal('code'), lang: LangSchema, src: z.string().max(1200), // ≤3 margin notes, pinned to a line notes: z.array(Note).max(3).optional(), dim: LineRange.optional(), // ≤8 lines, for the extension popup short: z.string().max(400).optional(), });
// answer — exactly one per item const ClozeCodeBlock = z.object({ kind: z.literal('clozeCode'), lang: LangSchema, src: z.string(), // holes written {{1}} holes: z.array(z.object({ id: z.number().int(), answer: z.string().max(60), accept: z.array(z.string()).max(6), width: z.number().int().max(24), // ch })).min(1).max(2), failure: z.string().max(240), // required });
Why failure is required and not optional
It is the sentence that names the concrete input where a near-miss breaks — search([4], 4) returns -1. A model that cannot write that sentence has not written an item about a boundary; it has written an item about syntax it happened to delete. Making the field required is the cheapest quality gate available, because Zod rejects the item and the generator retries without a human ever seeing it.
2 · What moves on shapes that already exist
Where
Change
PublicItemSchema
Gains blocks: Block[].optional(). prompt stays required — it is the accessible label, the extension fallback, and what every item generated before today already has. The answer key never ships: holes[].answer, accept and cases[].expect are stripped by the same public projection that strips answerIndex today (T-010).
items table
No column for blocks. items.payload is already jsonb holding the whole discriminated payload, so blocks live inside it and no migration touches this table. One column is added, and only for one query: answer_kind text, indexed — the extension’s due-item pick has to exclude formats that cannot render in a popup, and filtering on payload->'blocks' is neither indexable nor readable. NULL means “plain prompt”, which is every item that exists today.
concepts table
One column: domain — code | math | systems | prose, decided once during the concept-map pass. It is per concept, not per topic: “Big-O of a hash lookup” and “write a hash function” live in one topic and want different formats.
review_events table
One column: assisted boolean. Set when the learner took the skeleton hint. Without it a hinted pass and a cold pass are the same row, and the day-30 retention number quietly inflates.
3 · The prompt change is a new file, not a longer one
llm/prompts/items/ system.md ← unchanged user.md ← +1 line domains/ code.md ← new math.md ← later systems.md ← later
system.md keeps every rule that is about learning — the four types, one of each, one or two transfer items, the 200-character rubric cap. None of that is category-specific and none of it should be duplicated four times.
domains/code.md is appended only when the concept’s domain is code. It adds the block vocabulary, the format-per-concept-shape table, and one fully worked example. A topic on Renaissance painting never sees a word of it — and never spends a token on it.
## domains/code.md (excerpt) Pick the format from what the concept IS, not from what is impressive: a rule with a boundary → clozeCode over the condition a failure mode → hotspotLine, or recognition on the output an ordered procedure → orderLines a capability → codeEditor (at most ONE per concept) a distinction → recognition, options in mono none of these → plain recall — this is a correct answer, not a fallback Every clozeCode item MUST carry `failure`: one sentence naming a concrete input where the most likely wrong answer breaks. If you cannot write it, the blank is not on the boundary — move it, or write a different item. Hard limits. ≤12 lines per listing. ≤2 holes. ≤3 margin notes. Runnable, idiomatic code — never pseudocode, never `// ...` where the concept lives.
Cost check, against the measured baseline from T-074 (73 calls, 91k in / 48k out, $0.46 for a 40-concept topic): the fragment adds roughly 600 input tokens to each of the ~40 item calls and lengthens the outputs. Expect the topic to land near $0.60–0.70. Worth measuring on the first real topic rather than trusting this line.
4 · What Zod refuses, so a human never has to
Two answer blocks, or none. superRefine counts them — the renderer has one answer slot and grading has one boolean.
A {{2}} in src with no matching hole, or a hole with no marker. Both are silent blanks at runtime.
A note.line past the end of the listing — the model miscounts lines more often than it gets the concept wrong.
A codeEditor with fewer than two cases, or whose first case the empty starter already passes.
A short variant over 8 lines, or one that elided the line the question is about.
Any block on a concept whose domain is not code. Categories cannot borrow each other’s renderers by accident.
