The one line you were missing
return (...args) => {
+
clearTimeout(t);
−
setTimeout(() => fn(...args), ms);
+
t = setTimeout(() => fn(...args), ms);
};
You had the closure and the spread right; what was missing is that t has to be assigned for the next call to have something to cancel. A timer you never keep a handle to is a timer you can never stop — which is the same mistake as the effect that never cleans up.
Done for today
This concept comes back in a day, as a blank — not as this.
Deliberately not an IDE
No autocomplete, no inline type hints, no red squiggles while typing. Every one of them is a retrieval cue, and a retrieval cue is the thing being measured. Bracket matching, indent-on-newline and undo stay — those are typing, not knowing.
An assisted pass is not a pass
“Show me the shape” reveals the skeleton with the bodies blank. Taking it sets assisted = true on the review event, and the scheduler treats the answer as a lapse regardless of the cases going green. Otherwise day 30 comes as a shock.
Only JavaScript actually runs
JS and TS execute in a sandboxed iframe with a 2-second budget, so “Run the cases” is real. Every other language shows the identical screen with Submit instead, and the cases are graded server-side against the model answer. A learner should not be able to tell which one they are looking at until they press the button.
One per session, never in a review
Four minutes is a quarter of the daily budget. This block earns its place once, for a concept that is genuinely a capability — and when the same concept comes due on day 8, it comes back as a thirty-second blank instead. Reviews have to stay cheap or they stop happening.
