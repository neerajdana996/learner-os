Code — what a question is made of
A prompt string can’t ask about an off-by-one. Blocks can.
Category 1 of 5 · code
What does not change
item.type still decides the cognitive act — recall, recognition, application, explain. Every pilot number is sliced by it, so it stays exactly as it is.
Blocks decide what the act looks like. A fill-in-the-blank is still an application item. It is just no longer a textarea.
What changes
prompt: string becomes blocks: Block[] — and the generator chooses the shape, per concept, at generation time.
prompt stays as the plain-text fallback: screen readers, the extension popup, and every item generated before this shipped.
Anatomy — every code item, whatever its format
Context · 0–3
The setup the learner reads. Prose, a code listing, a diff, terminal output. Never interactive.
Answer · exactly 1
The one thing the learner does. Never two — two answer surfaces means two things graded as one, and the metrics stop meaning anything.
Reveal · 0–2
Shown only after answering: the working version, the real output, why the near-miss was a near-miss.
The renderer walks the array. It does not know it is looking at code — every category rides the same three slots, which is why maths and system design can land later without touching the session screen.

Time is the constraint nobody can argue with: the daily budget is 15 minutes and a session already carries two new concepts plus six reviews. So codeEditor is rationed — at most one per session, never in a review — and the twenty-second blocks carry the volume.
What the generator is told to pick, and when
The concept is a rule with a boundary
Off-by-one, the empty case, the inclusive bound, when a guard fires.
→ clozeCode over the condition
The concept is a failure mode
A leak, a race, a stale closure, an infinite re-render.
→ hotspotLine, or predict-the-output
The concept is a procedure
Set up, then subscribe, then return the teardown — in that order or it breaks.
→ orderLines
The concept is a capability
“Write a debounce.” Nothing short of writing it is evidence.
→ codeEditor, once per session
The concept is a distinction
Two things that look alike and are not: let vs var, map vs flatMap.
→ recognition, options as code
The concept is a why
Nothing to type. The answer is a sentence about a trade-off.
→ explain, plain text — unchanged
A concept that fits none of these gets a plain recall item, as today. That is the correct outcome, not a fallback — forcing a format onto a concept that does not have one produces a question about the format.
