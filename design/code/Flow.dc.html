Topic profile — 1 call
proposed
Nothing in the pipeline decides what language the topic is written in, and forty item calls each decide it privately. A learner on “Dynamic programming” gets Python on day 3 and JavaScript on day 11, from the same course. It is invisible today because a prompt string hides it. It stops being invisible the moment items contain real listings.
One cheap call fixes it for the whole topic: language, styleNotes (const over let, async/await over .then), and for a systems topic the componentVocabulary the renderer knows how to draw. Then every item call is told, rather than guessing.

Found while drawing this — the Day-30 test
The test is 25–30 items and T-038 generates them for held-out concepts on demand, from the same pool. Three codeEditor items in it is twelve minutes of a surprise test people already have to be persuaded to sit — and a learner who abandons it produces no Day-30 number at all, which is the pilot's entire output.
The extension's eligibility filter has to cover the test too. Neither T-038 nor T-089 says so today.
What the profile call costs
One call against T-074's measured 73. Against a topic at ~$0.46 and ~9 minutes, it is noise — and it removes forty independent style decisions, which is the kind of incoherence a learner reads as “this course was generated” without being able to say why.
Where it does not go
Not in the map call. That call is already the longest and most expensive thing in the pipeline, its output is the foundation for thirty days, and asking it to also fix a language and a house style is how a 40-concept map quietly becomes a 22-concept one.
