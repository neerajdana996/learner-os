Read this first — syntax colour flips with the surface, not the theme
.teach__card--retrieval already sets background: var(--ink). In light mode that is #2b2723 — dark. In dark mode --ink is #f5f1ec — light. The retrieval card is always the opposite of the page.
So a syntax palette keyed to prefers-color-scheme is wrong half the time. Define the palette as two mixins keyed to the surface and apply them by container. Getting this wrong produces dark-on-dark code in dark mode, which no light-mode screenshot will ever show you.

4 · Reuse, do not reinvent
@include card — every context block that needs a container. Never re-type the border and radius.
@include focus-ring — on .cloze__hole and every .hotspot__line. It is defined once for a reason.
@include control — Run, Check, Show me the shape. They are .button, not new buttons.
@include visually-hidden — the hotspot radios, and the “blank 1 of 2” label on each hole.
$tap — every line, chip and hole clears it. $s-* for spacing, $font-mono for every listing.
.u-rise-in — reveal blocks enter with it, exactly as .teach__card does. No new keyframes.
.choice / .choice--inline — the token bank and the confidence tap. One control, three sizes, already built.
@include until($breakpoint-sm) — where the notes rail collapses and the cloze switches to chips.
